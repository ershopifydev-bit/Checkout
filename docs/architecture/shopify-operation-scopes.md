Reviewed: 16 October 2026. Checklist: **1.1.2.1.1**. Coverage: master specification §§1–9, including all 13 platform routes in §7, merchant administration, reconciliation, analytics and optional enhancements. Versioned references below displayed **2026-10**; the scope catalog is unversioned. This is a requirements map, not a granted-permission inventory or final API-version selection.

The installation at PR #2 commit `d5d29b9` declares `scopes = ""`. The cart probe at PR #4 commit `a74bcb8` calls Storefront `cartCreate` and `cart`; it does not call the Admin API. This change adds no requested scopes, subscriptions or customer access. The future alternatives below remain disabled until their implementation and eligibility gates pass.

## Permission boundaries

Shopify distinguishes Admin, Storefront and Customer Account permissions. Write scopes include corresponding read access; request only the needed operations. Inspect actual granted scopes rather than treating configuration as authorization. Headless Storefront permissions are managed through that channel. [Scope catalog](https://shopify.dev/docs/api/usage/access-scopes)

Tokenless Storefront access supports basic products, selling plans and cart read/write. Authenticated Storefront requests use public or private Storefront tokens; Admin tokens are not interchangeable. Private server requests resulting from buyer traffic also require the buyer-IP header. Tokenless support does not bypass locked channels or product-publication requirements. [Storefront authentication](https://shopify.dev/docs/api/storefront/latest#authentication)

The matrix lists the minimum resource permission for the selected operation, not every field that could be added to its selection set. Additional protected fields, staff permissions, feature/plan eligibility and buyer authentication must be checked separately. Unknown operation requirements mean **do not request permission or execute the operation**, not “try a broader scope.”

## Cart, identity and checkout

| Product operation                                                                                                 | Shopify operation / authorization                                                      | Minimum permission or explicit exclusion                                                                                       | Delivery condition                                                                                             |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Read published variants, prices and availability                                                                  | Storefront product queries                                                             | Tokenless basic catalog; token-based `unauthenticated_read_product_listings`                                                   | Use published storefront data, not an Admin catalog import.                                                    |
| Read selling plans for a selection                                                                                | Storefront selling-plan fields                                                         | Tokenless supported fields; token-based `unauthenticated_read_selling_plans`                                                   | A selected selling plan does not require managing subscription contracts.                                      |
| Read exact inventory quantities                                                                                   | Storefront `quantityAvailable`                                                         | `unauthenticated_read_product_inventory`                                                                                       | Deferred; do not request if availability and cart validation suffice.                                          |
| Create Buy Now cart, add/update/remove lines, update attributes, buyer context, delivery choice or discount codes | Storefront Cart mutations                                                              | Tokenless supported cart operations; token-based `unauthenticated_write_checkouts`                                             | Revalidate exact mutation/fields and buyer authorization before each feature lands.                            |
| Read existing cart, totals and `checkoutUrl`                                                                      | Storefront `cart`                                                                      | Tokenless supported cart reads; token-based `unauthenticated_read_checkouts` (covered by write permission when already needed) | Retain full private cart reference; do not replace with an Admin order mutation.                               |
| Follow Shopify checkout URL                                                                                       | Browser navigation                                                                     | No extra OAuth scope                                                                                                           | Cart access is not payment authorization; browser propagation remains unverified.                              |
| Read saved customer details/addresses through Customer Account API                                                | Customer query with buyer authorization                                                | Candidate `customer_read_customers`; field/authentication-state requirements also apply                                        | Identity model and protected-data approval remain open.                                                        |
| Save an address through Customer Account API                                                                      | `customerAddressCreate`; separately review update/delete operations before adding them | `customer_write_customers`                                                                                                     | Only if saving back to Shopify is selected; manual session address entry does not need it.                     |
| Read customer data on merchant's behalf                                                                           | Admin customer query                                                                   | `read_customers`                                                                                                               | Alternative, not a default substitute for buyer authorization; protected fields and ownership checks required. |
| Write customer data on merchant's behalf                                                                          | Admin customer mutations                                                               | `write_customers`                                                                                                              | Deferred; no such mutation is required merely to collect guest contact/address input.                          |
| Legacy Storefront customer operations                                                                             | Storefront customer API with appropriate customer access token                         | `unauthenticated_read_customers` / `unauthenticated_write_customers`                                                           | Unselected alternative; do not combine with Customer Account scopes speculatively.                             |

Resource permissions in the table come from the [scope catalog](https://shopify.dev/docs/api/usage/access-scopes). The [cartCreate reference](https://shopify.dev/docs/api/storefront/latest/mutations/cartCreate) defines cart creation and checkout URL output. The [Customer Account query](https://shopify.dev/docs/api/customer/latest/queries/customer) also exposes authentication-state requirements; these are not all requestable OAuth scopes. Validate the chosen customer flow against the [Customer Account reference](https://shopify.dev/docs/api/customer/latest) and the catalog's customer-scope section. [Address creation](https://shopify.dev/docs/api/customer/latest/mutations/customerAddressCreate) explicitly requires `customer_write_customers`.

## Merchant operations, synchronization and optional features

| Operation                                                                                    | Minimum permission / reference                                                                                                                                                                                       | Project boundary                                                                                                                                                 |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Installation/token exchange, current installation scope inspection, basic shop/plan evidence | Authenticated app session; no additional resource scope declared for basic [shop query](https://shopify.dev/docs/api/admin-graphql/latest/queries/shop). Inspect scopes using the catalog's granted-access guidance. | Request only selected basic fields. A shop plan does not establish all checkout capabilities.                                                                    |
| App-owned branding, flags, entitlements and diagnostic records                               | No Shopify scope for local database operations                                                                                                                                                                       | Server-side tenant authorization still required.                                                                                                                 |
| Read orders/transactions for completion, ERP synchronization and reconciliation              | `read_orders`; [orders reference](https://shopify.dev/docs/api/admin-graphql/latest/queries/orders) and scope catalog                                                                                                | Protected data applies. Default order window is 60 days; older history additionally requires approved `read_all_orders`, only if a documented use case needs it. |
| Initiate a Shopify refund                                                                    | `write_orders`; [refundCreate](https://shopify.dev/docs/api/admin-graphql/latest/mutations/refundCreate)                                                                                                             | Deferred financial action; separate authorization, idempotency and provider reconciliation. Read-only sync does not need this scope.                             |
| Cancel an order                                                                              | `write_orders`; [orderCancel](https://shopify.dev/docs/api/admin-graphql/latest/mutations/orderCancel)                                                                                                               | Deferred merchant operation; verify applicable user permissions and financial effects before enabling.                                                           |
| Apply a shopper's existing discount code                                                     | Storefront cart-write permission above                                                                                                                                                                               | No Admin discount-write permission needed simply to apply a code.                                                                                                |
| Create a Shopify discount for a selected offer/loyalty integration                           | `write_discounts`; [discountCodeBasicCreate](https://shopify.dev/docs/api/admin-graphql/latest/mutations/discountCodeBasicCreate)                                                                                    | Candidate only; loyalty reservation/commit with an external provider is not this operation.                                                                      |
| Read merchant discount definitions                                                           | `read_discounts`; scope catalog                                                                                                                                                                                      | Deferred unless the implementation needs definitions rather than Shopify's cart totals.                                                                          |
| Install a web pixel                                                                          | `write_pixels` plus `read_customer_events`; [webPixelCreate](https://shopify.dev/docs/api/admin-graphql/latest/mutations/webPixelCreate)                                                                             | Extension configuration, user permission, consent and data minimization remain separate gates.                                                                   |
| Create payment-method customization                                                          | `write_payment_customizations`; [paymentCustomizationCreate](https://shopify.dev/docs/api/admin-graphql/latest/mutations/paymentCustomizationCreate)                                                                 | Enhanced eligibility only; this permission cannot create a gateway.                                                                                              |
| Create an app subscription if API billing is chosen                                          | Authenticated app billing operation; [appSubscriptionCreate](https://shopify.dev/docs/api/admin-graphql/latest/mutations/appSubscriptionCreate) lists no additional resource scope                                   | Distribution/billing model undecided; merchant confirmation required by the flow. No invented `write_billing` scope.                                             |
| Receive uninstall/scope-change/privacy events                                                | Signature verification and configured subscriptions, not a new customer-write permission                                                                                                                             | Subscription requirements and durable handlers are separate tasks. Do not request erasure-mutation scopes merely to receive privacy requests.                    |
| Receive order events and reconcile missing deliveries                                        | Corresponding order-read access; verify exact topic requirements when configuring subscriptions                                                                                                                      | Payload protected-data access and raw-body signature verification still required.                                                                                |
| Build checkout/theme UI extensions                                                           | Extension targets/capabilities and merchant eligibility; no blanket OAuth “extension access” scope                                                                                                                   | Add a scoped row for every API call made by a future extension; do not request theme-write access just to deploy a theme extension.                              |
| Manage carrier services, native checkout branding or delivery customizations                 | No request in current implementation; operation selection required                                                                                                                                                   | External delivery quotes and local branding do not imply permission to change Shopify configuration.                                                             |
| Create test products through Admin API                                                       | `write_products`; scope catalog                                                                                                                                                                                      | Test setup only if automated creation is selected; prefer existing merchant-created fixtures. Never add this to runtime installation solely for test setup.      |
| Independent payment execution or creating/marking paid orders                                | No permission requested; blocked pending written approved model                                                                                                                                                      | Ordinary order-write access is not authorization to bypass Shopify checkout. Payments Platform scopes require their own approval and operation-specific review.  |

The broad resource mappings above use the [Shopify scope catalog](https://shopify.dev/docs/api/usage/access-scopes); per-operation links supply details for mutations. Candidate operations are not launch commitments. Shopify-side metafields, gift cards, store credit, subscription management, fulfillment writes and other unselected mechanisms are excluded; selecting one requires a new exact operation/field/scope review before implementation.

## Traceability to platform routes

This coverage check prevents a local endpoint from accidentally becoming a reason to request unrelated Shopify access:

| Platform route(s) from specification §7                                                              | Shopify dependency                                                                                                            |
| ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `POST /v1/checkout/sessions`, `GET /v1/checkout/sessions/:id`                                        | Cart create/read and catalog selection above; local opaque sessions need no additional Shopify scope.                         |
| `PATCH /v1/checkout/sessions/:id/customer`, `PATCH /v1/checkout/sessions/:id/address`                | Local consented input; cart buyer context only when supported. Saved Shopify data uses the chosen identity alternative above. |
| `POST /v1/checkout/sessions/:id/quote`                                                               | Cart/catalog reads and relevant cart mutations. No Admin discount or inventory write implied.                                 |
| `GET /v1/checkout/sessions/:id/delivery-options`                                                     | Selected external carrier; no Shopify scope unless a separately reviewed native operation is added.                           |
| `POST /v1/checkout/sessions/:id/loyalty/quote`, `POST /v1/checkout/sessions/:id/loyalty/redemptions` | Selected loyalty provider; native Shopify discount writes only if that integration is explicitly chosen.                      |
| `POST /v1/checkout/sessions/:id/continue`                                                            | Cart revalidation/checkout URL; no custom payment permission.                                                                 |
| `POST /v1/webhooks/shopify`, `POST /v1/webhooks/providers/:provider`                                 | Authenticated ingress; resource scopes belong to Shopify subscriptions/follow-up queries, not provider callbacks.             |
| `GET /v1/merchant/capabilities`, `GET /v1/merchant/operations`                                       | Trusted local evidence/diagnostics; basic shop facts or order reads only when specifically implemented.                       |

## Permission-change acceptance criteria

Before enabling a row: pin the actual API version and field selection, record why each scope is needed, validate distribution/plan/protected-data requirements, inspect granted permissions, and test both permitted and denied access. Scope changes must use the official authorization flow; revoke dependent capabilities when access disappears. Never interpret a successful HTTP status as approval if GraphQL reports errors or redacts data.

Checklist 1.1.2.1.1 records the operation mapping for the defined scope, including alternatives and explicit exclusions. It does not resolve distribution, identity, provider selection, protected-data requests, merchant review, or live scope verification. Extend this matrix in the same PR as any newly selected Shopify operation; do not treat it as a fixed permission bundle to enable all at once.
